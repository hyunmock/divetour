# 홈페이지 아키텍처

## 목표

다이빙투어 모임의 소개, 투어 일정, 회칙, FAQ와 완료된 투어 기록을 빠르고 안전한 정적 홈페이지로 제공합니다.

## 데이터 흐름

```text
Notion
  ├─ 투어 일정
  ├─ 회칙
  ├─ FAQ
  └─ 투어 상세 본문의 MYBOX 공유 폴더 링크
          ↓ 빌드 시 공개 데이터만 조회
GitHub Actions
          ↓ 검사 및 Astro 정적 빌드
GitHub Pages
          ↓ 외부 링크
네이버 MYBOX
```

MYBOX 접근 암호는 데이터 흐름에 포함하지 않습니다. 암호는 카카오톡 팀 채널에서만 공유합니다.

## 시스템별 책임

### Notion

- 홈페이지 원데이터의 단일 원본
- 콘텐츠 공개 상태와 표시 순서 관리
- 투어 본문의 MYBOX 공유 폴더 링크 관리

### GitHub

- Astro와 TypeScript 소스
- 공개 가능한 이미지와 다운로드 파일
- 자동 검사와 배포 설정
- 이관 전 문서의 보관

### GitHub Pages

- 빌드 시점에 생성된 공개 정적 페이지 제공
- 사용자 인증이나 비밀정보 저장을 담당하지 않음

### 네이버 MYBOX

- 사진과 영상 원본 보관
- 공유 링크의 암호 기반 접근제어

## 공개 원칙

- 공개 승인된 Notion 항목만 빌드합니다.
- 완료된 투어의 사진·영상은 투어와 미디어 양쪽의 공개 조건을 모두 만족할 때만 표시합니다.
- Notion API 조회나 검증이 실패하면 배포를 중단하고 기존 사이트를 유지합니다.
- 정적 사이트에 비공개 데이터나 암호를 내려보낸 뒤 화면에서 숨기는 방식은 사용하지 않습니다.

## 배포 계획

Phase 1에서는 저장소 쓰기 권한이 있는 담당자가 GitHub Actions에서 기본 브랜치의 게시 워크플로를 수동 실행합니다. 워크플로는 최신 Notion 자료의 공개 조건을 검증하고 Astro 정적 빌드가 성공하면 GitHub Pages에 배포합니다. Notion 편집과 코드 병합만으로는 게시되지 않습니다. 기존 ChatGPT Site는 새 배포본 검증이 끝날 때까지 유지합니다.

Phase 2에서도 홈페이지는 GitHub Pages에 둡니다. 관리 화면에서 게시를 요청하면 서버리스 함수가 로그인 세션과 현재 운영자 권한을 확인한 뒤 GitHub REST API로 Phase 1의 게시 워크플로를 실행합니다. 함수가 GitHub 호출용 인증 정보를 관리하므로 운영자는 개인 계정에 저장소 쓰기 권한이 없어도 게시할 수 있습니다. 게시 요청자와 실행 결과는 함께 기록합니다. 운영자 명단과 게시 기록은 공개 정적 파일에서 제외합니다.
